# Portfolio Website — Revised Employer-Focused MVP

**Status:** Revised plan, ready for implementation review  
**Goal:** Build a professional portfolio that demonstrates software development, Python, and data science skills.

## 1. Website Structure

### Homepage

The homepage should immediately communicate who I am, what I do, and what I have built.

**Sections, in order:**

1. **Introduction:** Name, Data Science student background, technical interests, and a short professional statement.
2. **Featured Projects:** Three clearly visible projects with screenshots, descriptions, technologies, and direct links.
3. **Technical Skills:** Programming languages, frameworks, development tools, and data analysis skills I can demonstrate.
4. **About Me:** Education, technical interests, career direction, and approach to problem-solving.
5. **Contact:** GitHub, professional email, and résumé when available.

Visitors should be able to reach any project directly from the homepage.

## 2. Featured Projects

**Project 1: To-do List Application**

Demonstrate application development, programming logic, and user interface design. Include actual features, technologies, screenshots, and a link to the repository.

**Project 2: Music Listening Dashboard**

Demonstrate data analysis, visualization, and interpretation. Clearly identify synthetic data and distinguish illustrative examples from verified results.

**Project 3: CSV Business Report**

Demonstrate Python-based data processing, calculations, and reporting. Include verified business metrics, code examples, and sample report outputs. Label unfinished functionality accurately.

## 3. Individual Project Pages

Each project receives its own dedicated page with the following structure:

1. **Overview:** What the project does.
2. **Problem:** What challenge the project addresses.
3. **Technologies:** Languages, libraries, and development tools used.
4. **Implementation:** How the solution was developed and important technical decisions.
5. **Demonstration:** Real screenshots, sample outputs, or working demonstrations.
6. **Results:** Verified outcomes and what the project accomplishes.
7. **Challenges and Improvements:** Problems encountered, how they were solved, and future improvements.
8. **Source Code:** A clearly visible GitHub link when available.

No fabricated results, screenshots, or technical accomplishments.

## 4. Technology Stack

- **Astro:** Static website generation.
- **TypeScript:** Data handling and development checks.
- **Plain CSS:** Responsive layouts and styling.
- **Small JavaScript scripts:** Theme and simple interface interactions.
- **portfolio.json:** Centralized project information.
- **GitHub Pages:** Free website hosting.
- **GitHub Actions:** Automated builds and deployment.
- **Playwright:** Focused browser testing.

No React application, backend, database, CMS, animation engine, or complex charting framework is required.

## 5. Design Direction

The design should be modern, minimal, and professional.

**Include:**
- Strong typography and clear spacing.
- Clean project cards with screenshots.
- Light and dark themes.
- Mobile-friendly layouts.
- Clear navigation and visible links.
- Accessible keyboard navigation and reduced-motion support.
- Subtle animations that never delay content.

**Exclude from MVP:**
- Interactive 3D.
- Sound effects.
- Complex scrolling animations.
- Elaborate introduction screens.
- Unnecessary dashboards.
- Blog and online store.
- Live API integrations.

Use Ryan Fitzgerald's Dev Portfolio as the structural reference and the original inspiration site only as a visual reference. Do not copy personal assets or unlicensed source code.

## 6. Development Phases

**Phase 1 — Content Preparation**

Verify the three projects, screenshots, technologies, repositories, and available results. Draft accurate professional descriptions.

**Phase 2 — Website Foundation**

Create the Astro project, shared layout, homepage, centralized data file, navigation, and project routes.

**Phase 3 — Project Presentations**

Build all three case-study pages. Add verified evidence, screenshots, relevant results, and GitHub links.

**Phase 4 — Design and Testing**

Apply responsive styling, light/dark themes, basic transitions, and accessibility improvements. Test navigation, mobile layouts, links, and JavaScript-disabled content.

**Phase 5 — Deployment**

Publish to GitHub Pages, verify the public URLs, document how to update the website, and prepare optional custom-domain support.

## 7. Definition of Done

Version 1 is complete when:

- All three projects have functional pages.
- All technical claims and results are accurate.
- Available GitHub and demonstration links work.
- The website works on desktop and mobile.
- Keyboard navigation and reduced-motion behaviour work.
- Visitors can easily find project evidence.
- Real contact information and a résumé are available, or missing links are omitted until supplied.
- The website is deployed to a working public URL.
- Instructions for updating projects are documented.

**Success criterion:** An employer should understand my technical interests within 10 seconds and be able to inspect evidence from a featured project within two clicks.
